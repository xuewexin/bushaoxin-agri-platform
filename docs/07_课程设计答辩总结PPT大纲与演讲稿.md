## 答辩现场高频 Q&A 专家问答预演

**Q1：老师提问：为什么选择单体分层架构而不是直接采用 Spring Cloud 微服务？**
> **回答要点**：
> “非常感谢老师的提问。我们在可行性研究阶段对架构选型做了专项权衡：当前系统核心定位是农产品产销撮合，业务内聚度高。采用 SpringBoot 单体分层架构搭配 Redis 缓存，单机 QPS 足以支撑数千并发，且能避免分布式事务（如 Seata）带来的网络开销与运维复杂度。未来随着业务规模指数级扩张，系统各模块边界划分清晰，可以平滑低成本地解耦拆分为独立微服务。”

**Q2：老师提问：直播间并发抢购时，如何确保商品库存不会发生超卖（减成负数）？**
> **回答要点**：
> “我们采用了‘两道防线’策略：第一道防线在应用层与缓存层，利用 Redis Lua 脚本进行原子性库存预扣减，高并发流量在缓存层被迅速拦截或放行；第二道防线在持久层，数据库更新语句采用了乐观锁条件更新：`WHERE id = ? AND stock >= ?`，借助 MySQL 行级排他锁，彻底从数据库底层杜绝了并发脏读和负库存。”

**Q3：老师提问：大宗批发和零售普通单在系统业务逻辑和数据结构上有什么区别？**
> **回答要点**：
> “两者的商业逻辑完全不同：零售单采用 C 端标准化流程（一口价、即时支付、快递直发）；而大宗采购属于 B 端非标交易，量大（吨级起步）、金额高，必须先经过‘在线多轮询价磋商’，达成一致后由系统生成具有法律效力的《电子意向订单合同》，并支持线下实地预约验货看样，因此我们在数据表上专门独立了 `tb_wholesale_inquiry` 状态机来驱动这一复杂流程。”
